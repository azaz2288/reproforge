# Findings

- Existing portfolio has several small, useful tools but no unified execution/provenance platform. A local-first auditable pipeline engine is a distinct, practical flagship theme.
- Chronoguard and CSV Quality Gate may later be integrated as policy adapters; M1 must stand alone and have a useful vertical slice.
- Project-root-relative paths and explicit source/dependency contracts make provenance testable; they do not create an OS security boundary.
- The first two-step example runs successfully: validation topologically orders `summary` before `report` despite reversed config order; the run stores input, output and log objects by SHA-256, and `verify` accepts the untouched ledger. The observed run ID was `1cf656c772604b2f93e9a376f759c48f` in ignored local state. Audit hardening must still test malformed references and record/status inconsistencies.
- M1 was published as a public work-in-progress and passed Windows/Ubuntu CI. For M2, cache reuse must be two-key opt-in: a task declares `cache=true` and a run explicitly uses `--reuse`. The cache key includes full plan bytes, command, declared input object references, declared outputs and runtime metadata; this cannot detect undeclared inputs, network calls or nondeterministic commands, so the limitation must remain prominent.
- M2 cache hardening: cache indexes are written only after the complete successful run ledger is durable; a hit rejects incomplete/failed or mismatched source runs, input/command drift, corrupt objects and inconsistent log previews. The run ledger itself is not signed, so a malicious party with write access to both ledgers and objects can still forge history.
- OS-backed per-project lock serializes writers and is released on process death; `recover` can classify abandoned running ledgers after taking that lock. It does not resume a partially completed command or undo side effects.
- Built-in gates are first-class tasks, so failure propagation uses the existing DAG scheduler. Their JSON reports are stored as objects and `verify` independently reevaluates the stored CSV; this gives stronger evidence than trusting the report alone. The temporal rule is a strict chronological holdout check, not a general proof against all leakage.
- Local dashboard binds 127.0.0.1, escapes ledger text, and rejects POST. It is not an authenticated multi-user service; do not expose it on a network.
- UCI's historical Iris source URL was reachable on 2026-09-30 (HTTP 200, 4,551 bytes) and returned 150 unlabeled-header rows plus trailing blank line. It can be used for an opt-in, pinned real-data case without claiming a temporal validation use case.
- SHA-256 of the downloaded raw UCI Iris bytes is `6f608b71a7317216319b4d27b4d9bc84e6abd734eda7872b71a458569e2656c0`; a fetch helper can require this digest before converting to a local CSV with an explicit header.
